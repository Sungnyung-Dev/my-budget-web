# CRUD UI 브라우저 검증

추가 테스트 라이브러리 없이 실제 React 컴포넌트·공통 상태 저장소·API 클라이언트에 모의 `fetch`를 연결합니다. 테스트 진입점은 `tests/browser/` 안에만 있으며 일반 앱과 프로덕션 번들에서는 import하지 않습니다.

```bash
npm run dev
```

서버의 로컬 주소 뒤에 `/tests/browser/index.html`을 붙여 Chrome에서 엽니다. 기본 주소는 `http://localhost:5173/tests/browser/index.html`입니다. 첫 화면에서 390px 전체 시나리오를 실행하고 320·430·768·1280·1440px을 순서대로 검사합니다. 공통 클라이언트의 실제 10초 타임아웃을 포함하므로 완료될 때까지 기다립니다. 결과는 페이지 상단과 탭 제목에 PASS/FAIL로 표시합니다. `?width=390` 등은 해당 폭의 숫자·조회 상태·레이아웃·빈 서버 시나리오를 실행합니다. 전체 CRUD·타임아웃 시나리오는 기본 주소의 첫 390px에서 실행합니다.

모든 요청은 인메모리 모의 서버가 응답합니다. 기존 `globalThis.fetch`를 보관하거나 호출하지 않으며 예상하지 않은 경로·메서드는 실패합니다. 테스트용 카테고리·거래는 브라우저 메모리에서만 존재합니다. 서버에서 쓰기가 이미 처리된 뒤 응답만 유실되는 상황도 모의하며 실제 운영 서버에는 쓰기를 보내지 않습니다.

2026-11-23 Chrome 검증 결과: **390px 176개 + 320/430/768px 각 106개 + 1280/1440px 각 104개 = 702개 확인 통과**. 별도의 Node 테스트 `npm test` 482개와 구분합니다. `npm run typecheck`는 브라우저 TSX도 검사합니다.

카테고리 정렬 검증은 모든 폭에서 실행합니다. 모바일 TouchEvent의 300ms 길게 누르기·이동·종료, 짧은 터치·지연 전 이동·같은 위치 드롭·취소 시 미저장, 핸들의 스크롤 차단과 행 본문의 기본 스크롤 허용을 검사합니다. PC는 위·아래 버튼과 첫·마지막 경계를 검사합니다. 모의 PUT 한 번 전송·저장 중 재정렬 잠금·응답 전 기존 순서 유지·실패와 불확실한 결과 후 재조회, 유형별 독립 정렬, 재조회 후 순서 유지, 거래 추가·수정 선택지 반영을 확인합니다. 실제 모바일 Safari의 터치 동작은 실기기에서 별도로 확인해야 합니다.

- 실제 UI 버튼을 통한 거래·카테고리 생성·수정·삭제와 성공 뒤 시트 닫기, 서버 ID·최종 금액·이름 반영, 삭제 204 전 목록 유지.
- 저장 중 입력·닫기·Escape·배경 클릭 차단, 연속 submit과 삭제 중복 클릭 방지, 낙관적 표시 없음.
- 6개 작업의 HTTP 409 거절 시 입력값·삭제 확인 유지와 내부 오류 정보 비노출.
- 타임아웃·네트워크 오류·5xx 뒤 추가 저장·삭제 차단. 시트를 닫거나 다른 입력 시트를 열어도 공통 `needsRefresh` 유지.
- 수동 GET 실패 시 목록·입력·차단 유지, GET 중 입력·닫기 잠금, 성공해도 입력·삭제 확인 유지. 이미 삭제된 대상 재삭제 차단과 늦은 응답 무시, 목록에서 처리 결과 확인 안내.
- 이름 중복의 기존 도메인 검증, 사용 중 카테고리 삭제 제한, 이름 변경이 홈·통계에 반영되는지 확인.
- 홈·내역·월간/연간 통계·12개월 차트의 같은 합계와 연도 경계, 과거 연도를 포함한 사용 건수, 불필요한 GET 없음.
- 서버의 정상 빈 배열에서 첫 카테고리·거래 생성, 카테고리만 있을 때 실제 선택지 표시.
- 각 폭에서 전체 탭·카테고리 화면의 가로 넘침, 모바일 탭·PC 사이드바, 시트 최대 580px 폭·92% 높이·내부 스크롤.

iframe의 실제 CSS 뷰포트 크기를 고정해 반응형을 검사합니다. 실제 iPhone Safari의 키보드·Safe Area·설치 검증은 포함하지 않습니다. 운영 API 쓰기와 재조회 후 실제 서버 데이터의 일치는 사용자가 일반 앱에서 별도로 확인합니다. 직접 테스트할 때는 생성·수정·삭제가 실제 운영 데이터에 반영됩니다.

숫자·FAB·헤더 수정 검증은 모든 폭에서 실행합니다. 최초 GET을 대기·실패·재시도로 진행해 0원 화면과 구분하고, 미준비 Summary도 직접 검사합니다. 정상 빈 월간/연간 수치와 거래가 있으나 차액이 0인 경우를 확인합니다. 1,000건 거래·1,000개 카테고리의 건수, 1/1,000/10,000/1,000,000원 목록, 음수 차액과 차트 포맷을 검사합니다. 0·소수 입력은 여전히 전송 전에 차단합니다.

FAB는 45px 원형·탭 위 13px·투명 컨테이너·본문까지 이어지는 스크롤 영역을 검사합니다. 버튼 바깥 hit test가 본문에 도달하고, 마지막 거래가 FAB 위에서 끝나며 탭 높이가 늘어도 위치를 맞추는지 확인합니다. PC는 공통 헤더가 DOM에서 없어지고 본문 top이 0인지, 각 화면 제목과 사이드바는 유지되는지 검사합니다. Chrome에서 1440px PC 화면과 390px 모바일 FAB 모양·실제 클릭·Escape도 직접 확인했습니다.
