# 나의 가계부 · Web

기존 React Native iOS 가계부를 웹으로 옮기기 위한 React + TypeScript + Vite 기반입니다. 반응형 PWA, 원본 시안의 화면·입력 시트, iOS 도메인 로직, 서버 Ledger 조회와 거래·카테고리 쓰기 API·상태 관리를 구현했습니다. 최초 실행과 수동 새로고침으로 서버 Ledger를 조회해 홈·내역·통계·설정에 표시합니다. 기존 거래·카테고리 입력 시트의 저장·수정·삭제 버튼을 공통 상태의 CRUD 작업에 연결했습니다. 서버가 확인한 결과만 화면에 반영합니다.

## 실행과 검사

Node.js 22.12 이상(검증 환경: Node.js 24)과 npm을 사용합니다.

```bash
npm ci
npm run dev
```

터미널에 표시되는 로컬 주소를 엽니다. 기본 주소는 `http://localhost:5173`입니다.

```bash
npm run typecheck
npm test
npm run build
npm run preview
```

`build`는 TypeScript 검사 후 `dist/`에 정적 앱, `manifest.webmanifest`, `sw.js`, Workbox 파일을 생성합니다. `preview`의 기본 주소는 `http://localhost:4173`입니다.

`test`는 추가 라이브러리 없이 Node의 TypeScript 지원과 기본 테스트 러너를 사용합니다. 기존 도메인·조회·화면 데이터 테스트 185개와 [쓰기 API·상태 테스트](src/state/README.md) 214개, 표시 포맷 테스트 8개를 더해 총 407개를 실행합니다. `typecheck`에는 테스트 코드 검사도 포함됩니다. HTTP 테스트는 모두 모의 응답을 사용하며 기존 PWA 캐시 정책을 유지합니다. 브라우저 상호작용 검증은 아래 CRUD 절차를 별도로 실행합니다.

초기 검증에서 개발 서버 HTTP 응답, TypeScript 검사, 프로덕션 빌드, PC·320/390/430px 화면, 탭·기간·날짜 선택을 확인했습니다. Chrome에서 Worker 활성화, 정적 리소스 10개 저장, 오프라인 새로고침도 확인했습니다. 실제 iPhone Safari 설치는 아직 검증하지 않았습니다.

`App`의 공통 `useLedger()` 상태에서 검증된 전체 Ledger를 각 화면에 전달합니다. 최초 조회 중에는 로딩 안내만 표시하고 실패하면 오류·재시도를 표시합니다. 정상 응답의 빈 배열은 실제 0원·0건으로 표시합니다. 재조회 중과 실패 뒤에는 마지막 정상 데이터를 유지하며 안내합니다. 탭 변경은 GET을 추가하지 않고 선택한 월·날짜도 유지합니다. 새로고침하면 홈에서 시작해 서버를 다시 조회합니다. 내역의 + 버튼으로 생성하고 홈·내역의 거래를 선택하면 수정·삭제할 수 있습니다. 설정의 카테고리 관리에서도 추가·이름 변경·삭제가 가능합니다. 데모 생성·로컬/오프라인 거래 저장은 없습니다. 자세한 데이터 흐름과 검증은 [상태 계층 문서](src/state/README.md)를 참고합니다.

## CRUD UI 동작과 검증

`TransactionEditor`와 `CategoryEditor`는 `App`의 동일한 `useLedger()` 작업을 전달받습니다. 입력 검증 → 기존 store의 6개 CRUD 작업 → 서버 응답 및 전체 Ledger 검증 → 공통 상태 반영 → 성공 시 시트 닫기 순서입니다. 화면별 합계·차트·카테고리 사용 건수는 갱신된 동일 Ledger에서 다시 계산합니다. 카테고리 추가의 기본 심볼은 iOS와 같이 지출 `other`, 수입 `income`이며 이름 변경은 type/symbol을 변경하지 않습니다.

- 저장·재조회 중에는 필드, 저장·삭제·취소·닫기, Escape·배경 닫기를 잠급니다. 중복 submit도 차단합니다.
- 확정된 서버 거절은 안전한 오류만 표시하고 입력과 삭제 확인을 유지합니다.
- 불확실한 실패는 `needsRefresh` 안내와 수동 GET 버튼을 표시하고 추가 쓰기를 차단합니다. 재조회 실패 시 기존 목록·차단을 유지합니다. 재조회 성공으로 입력을 초기화하거나 시트를 닫지 않습니다. 목록에서 이미 처리되었는지 먼저 확인하도록 안내하며 같은 쓰기를 자동으로 재전송하지 않습니다.
- 재조회에서 삭제된 대상은 다시 저장·삭제할 수 없습니다. 카테고리 사용 건수는 현재 공통 Ledger의 전체 거래로 계산하며 사용 중 삭제를 제한합니다.

`npm run dev` 후 **`http://localhost:5173/tests/browser/index.html`**을 열면 모의 HTTP와 실제 React 상태 저장소로 CRUD·실패 복구·반응형 검증을 실행합니다. 이 테스트 진입점은 실제 `fetch`를 호출하는 경로가 없고 운영 API에 연결하지 않습니다. 테스트용 거래·카테고리는 메모리에만 존재하며 프로덕션 빌드에 포함되지 않습니다. 특정 폭은 `?width=390` 등으로 볼 수 있습니다. 타임아웃 검증은 공통 클라이언트의 실제 10초를 기다립니다. 브라우저 테스트 파일도 `typecheck`에 포함됩니다.

실제 운영 서버에 쓰는 수동 테스트는 사용자가 별도로 수행합니다. `npm run dev`의 일반 앱 주소에서는 저장·삭제 버튼이 실제 API를 호출하므로, 직접 추가·수정·삭제하고 재조회 후 홈·내역·통계·사용 건수의 일치를 확인해 주세요. 자동 검증에서는 운영 API 쓰기를 수행하지 않았습니다. iPhone Safari의 키보드·Safe Area·홈 화면 설치는 실기기 확인이 필요합니다.

## 숫자 표시와 반응형 UI 수정

- `formatNumber`를 금액·건수 표시의 공통 기반으로 사용합니다. 기존 `formatMoney`는 절댓값 금액, `signedMoney`는 수입·지출·차액의 부호를 담당합니다. 금액·거래 건수·카테고리 사용 건수·통계 지표·차트 접근성 안내에 쉼표를 적용하고 `toLocaleString` 중복을 제거했습니다. 정상 계산값 0과 -0은 부호 없이 `0`입니다. 내부 정수와 API 전송, `parseAmount`의 입력 규칙은 유지합니다.
- 정상 조회된 빈 거래의 숫자는 `0`으로 표시합니다. 최초 로딩·오류 화면은 유지하고 미준비 Summary는 `—`로 구분합니다. 빈 목록 안내는 유지합니다.
- FAB 주변 흰 띠의 원인이던 본문 바깥의 74px margin을 스크롤 안쪽 padding으로 옮겼습니다. FAB 컨테이너는 투명하며 크기 45px·탭 위 13px·Safe Area 계산과 클릭 동작은 그대로입니다. 마지막 거래는 스크롤 끝에서 FAB 위에 표시됩니다.
- PC 공통 가로 헤더와 77px 높이·관련 CSS를 제거했습니다. 본문은 상단부터 시작하며 사이드바·모바일 탭·화면 내부 `MY LEDGER`와 제목은 유지합니다.

검증: `npm run typecheck`, `npm test` **407개**, `npm run build` 통과. [Chrome 모의 UI 검증](tests/browser/README.md)은 **320·390·430·768·1280·1440px의 550개 확인**을 통과했습니다. 0/1/1,000/10,000/1,000,000/음수, 정상 빈 데이터·미준비·로딩·오류, 1,000건 목록, FAB 투명 영역의 본문 접근·스크롤·클릭, PC 헤더 제거·사이드바와 기존 CRUD를 검사했습니다. 실제 iPhone Safari의 키보드·Safe Area 확인은 별도입니다. PWA·API·공통 상태·집계·검증 로직과 패키지 의존성은 유지합니다.

## 서버 API와 공유 상태

`src/lib/api/ledgerApi.ts`의 `await getLedger()`는 `/api/v1/ledger`를 GET하고 기존 `validateLedger`로 검증한 `LedgerData`를 반환합니다. 기본 10초 타임아웃은 본문 수신까지 포함하며 외부 `AbortSignal`도 지원합니다. HTTP·네트워크·타임아웃·응답·설정 오류와 호출자 취소를 구분하고 실패를 빈 배열로 바꾸지 않습니다. 사용법과 오류 코드는 [API 문서](src/lib/api/README.md)에 정리했습니다.

`npm run dev`의 `/api` 프록시는 기존 HTTPS 백엔드로 요청을 전달합니다. 빌드 결과에는 프록시가 없으므로 실제 배포 호스트에는 같은 출처의 `/api` 라우팅이 별도로 필요합니다. `npm run preview`의 프록시는 명시적으로 비활성화했습니다. GET과 거래·카테고리 CRUD는 모두 상대 경로 `/api/v1/...`와 `credentials: 'same-origin'`을 사용하여 브라우저가 관리하는 동일 출처 Nginx Basic 인증에 대응합니다. 사용자명·비밀번호·인증 헤더를 코드나 환경변수에 저장하지 않으며 HTTP 캐시·API 응답 캐시는 사용하지 않습니다. 운영 설정은 수정하지 않았고, 실제 Nginx 인증 적용과 HTTPS 배포 후 브라우저 동작 확인은 서버 배포 단계에서 진행해야 합니다.

2026-11-16 개발 프록시를 통한 실제 읽기 전용 GET은 HTTP 200 및 도메인 검증을 통과했습니다. 실제 거래 내용은 기록하지 않았고 단위 테스트는 모의 응답만 사용합니다. 현재는 React 화면의 조회와 CRUD 버튼을 연결했습니다. 천 단위 쉼표·정상 0 표시·FAB 배경·PC 헤더 제거까지 반영했으며 오프라인 저장은 포함하지 않습니다.

`transactionApi.ts`·`categoryApi.ts`에 생성·수정·삭제 6개 함수를 구현했습니다. 생성 201·수정 200의 서버 최종 객체를 사용하고 삭제는 204를 검사합니다. 공통 상태 계층은 입력 검증 후 `saving` 동안 데이터를 유지하며 다음 Ledger 전체가 검증된 경우에만 반영합니다. 쓰기와 GET은 동시에 실행하지 않습니다. 네트워크·타임아웃·서버 오류·잘못된 성공 응답은 `needsRefresh`로 추가 쓰기를 차단하며, 검증된 GET 성공 후에만 해제합니다. 실패 결과는 `{ ok: false, code, message, status?, needsRefresh }`이므로 입력 시트·삭제 확인을 유지할 수 있습니다. API 계약·사용법은 [API 문서](src/lib/api/README.md), 상태·UI 연결은 [상태 문서](src/state/README.md)에 정리했습니다. 이번 쓰기 검증은 모의 HTTP만 사용했으며 운영 서버에 POST·PATCH·DELETE를 보내지 않았습니다.

- **320–599px:** 단일 열과 고정 하단 탭(홈·내역·통계·설정).
- **600–1023px:** 모든 화면은 최대 580px의 단일 열과 하단 탭을 유지합니다.
- **1024px 이상:** 고정된 위치의 사이드바와 두 열 콘텐츠.
- `viewport-fit=cover`, `env(safe-area-inset-*)`, 동적 뷰포트 높이를 사용합니다. 모든 화면은 하단 탭 위에서 끝나는 별도 스크롤 영역을 사용합니다. 내역은 FAB 아래까지 본문을 스크롤하고 마지막 거래가 FAB에 가려지지 않도록 본문 안쪽에 여유 padding을 둡니다.
- 기본 키보드 탐색, 현재 메뉴 표시, 본문 건너뛰기, 날짜 선택 상태를 제공합니다.

아래 화면 제작 이력은 서버 연결 전 검증을 기록한 내용입니다. 현재 데이터·오류 처리는 위 설명과 상태 계층 문서를 기준으로 합니다.

### 홈 화면의 원본 재현

`references/ios_ledger_final_ui.html`과 `my-budget-ios/src/screens/HomeScreen.tsx`를 읽기 전용으로 참고했습니다. 내역과 `PageHeader`, `PeriodNav`, `components/ledger.css`의 색상 토큰·타이포그래피·빈 영역·Safe Area·스크롤 레이아웃을 공유합니다.

원본의 `MY LEDGER`, 29px 제목, 22px 좌우 여백, 31px 월 이동 버튼, 17px 모서리 지출 카드와 32px 금액, 9px 간격의 두 작은 카드, 16px 섹션 제목, 점선 빈 영역을 맞췄습니다. 최근 거래의 **전체 보기 ›**는 선택 월을 유지하며 내역으로 이동합니다. 월 이동 버튼과 전체 보기의 터치 높이는 44px입니다.

원본과의 차이는 태블릿의 580px 폭 제한, PC의 사이드바·2열 배치와 조회 상태 안내입니다. 서버 연결 후에는 검증된 월별 금액·비율·최근 거래를 표시하고, 실제 지출이 없으면 카테고리 막대 대신 빈 상태를 보여줍니다. 가짜 휴대폰 프레임·상태바는 앱에 포함하지 않습니다.

## PWA

`vite-plugin-pwa`의 `generateSW`를 사용합니다. 앱 이름·한국어·standalone 실행·시작 URL·범위와 192/512px PNG, maskable PNG, 180px Apple touch icon을 구성했습니다. 아이콘은 자체 제작한 흑백 장부 모양이며 `public/favicon.svg`에 벡터 원본이 있습니다.

- **캐시 범위:** 빌드된 JS/CSS/HTML/폰트, 명시한 아이콘과 Manifest만 precache합니다.
- `runtimeCaching`은 빈 배열입니다. API 응답, 거래 데이터, 외부 요청을 캐시하는 규칙이나 백그라운드 동기화는 없습니다.
- 문서 요청의 앱 화면 대체는 `/`, `/index.html` 및 해당 쿼리 문자열에만 적용됩니다. `/api` 경로는 제외합니다.
- 새 Worker는 사용자에게 업데이트 알림을 표시합니다. 사용자가 **새로고침**을 선택할 때 활성화합니다.
- 개발 중 캐시 간섭을 줄이기 위해 **개발 서버에서는 Service Worker를 등록하지 않습니다.** PWA 검증에는 `build` 후 `preview`를 사용합니다.
- 첫 온라인 방문 후에는 앱 화면을 오프라인에서 열 수 있습니다. 오프라인 거래 저장·수정 기능은 없습니다.

### 설치와 확인

실제 iPhone 설치와 Service Worker 실행은 HTTPS 배포 후 확인합니다. 개발 PC에서는 `localhost` 또는 `127.0.0.1`로 검증할 수 있습니다. iPhone에서 PC의 일반 HTTP LAN 주소로 접근하는 것만으로는 PWA 검증을 완료할 수 없습니다.

1. `npm run build` → `npm run preview` 후 브라우저에서 열고 한 번 새로고침합니다.
2. Chrome DevTools **Application → Manifest**에서 이름·아이콘·standalone 설정을 확인합니다.
3. **Service workers**에서 `sw.js`의 활성화를, **Cache storage**에서 정적 앱 파일만 저장되는지 확인합니다.
4. DevTools **Network → Offline** 후 새로고침하여 앱 화면이 열리는지 확인하고 다시 온라인으로 복구합니다.
5. iPhone에서는 HTTPS 주소를 Safari로 열어 **공유 → 홈 화면에 추가**로 설치하고, 독립 실행·아이콘·Safe Area·스크롤을 확인합니다.

설정 참고: [Vite PWA 공식 문서](https://vite-pwa-org.netlify.app/guide/), [업데이트 알림](https://vite-pwa-org.netlify.app/guide/prompt-for-update), [Workbox 캐시 설정](https://vite-pwa-org.netlify.app/workbox/generate-sw).
